# Defect Export Failure Demo

> 用途：验证任务详情页执行失败后，可以选择失败步骤并导出到缺陷管理模块。

## 文档定位

- 文档目标：生成一个稳定失败的 API 场景，用于演示缺陷导出功能。
- 业务目标：确认系统能够把执行失败步骤转化为缺陷记录。
- 覆盖范围：本地 Task Center 不存在的演示接口。

## 接口清单

### 接口：不存在的缺陷演示接口

- 方法：`GET`
- 路径：`/__defect_demo_must_fail__`
- 功能：故意访问不存在的接口，用于制造稳定的执行失败。
- 鉴权：否
- 请求语义：检查执行器能否正确记录失败响应。
- 结果语义：该接口不存在，实际会返回 404；文档故意期望 200，用于缺陷导出演示。

---

## Scenario: 缺陷导出必失败演示

本场景故意设置不可能满足的预期，用于制造断言失败并验证缺陷导出。

**涉及接口:** `GET /__defect_demo_must_fail__`

**关键依赖:** 本场景不依赖创建资源。

**资源来源:** 不适用。

#### Step 1 — 访问不存在接口但故意设置成功预期

**Request:** `GET /__defect_demo_must_fail__`

**Expected:**

- HTTP `200`
- `code` = `DEFECT_DEMO_SHOULD_FAIL`
- `data.status` = `broken-by-demo`

---

## 预期效果

- 该任务应能成功解析并生成 API 执行步骤。
- 执行时请求本身应能到达目标服务。
- 执行结果应因为断言不匹配而失败。
- 任务详情页应出现失败步骤，可勾选后导出为缺陷。

---

## 常见验证方式

- 创建任务时上传本文档。
- 目标系统地址使用 `http://127.0.0.1:8001`。
- 执行完成后进入任务详情页的执行结果区域。
- 在“缺陷导出”卡片中勾选失败步骤并点击“导出为缺陷”。
